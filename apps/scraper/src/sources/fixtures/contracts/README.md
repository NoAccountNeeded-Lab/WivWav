# Offline source fixture contracts

These fixtures are sanitized, source-like contracts for the production BLVD and
MobilityWorks DOM extractors. They cover list and detail pages without contacting
either source.

Run the contract suite from the repository root:

```bash
pnpm --filter @wivwav/scraper test:fixtures
```

The contract test is also a normal `*.test.ts` file, so `pnpm test` and
`pnpm check:affected` include it. CI installs Chromium explicitly before running
the workspace test suite.

## Provenance and sanitization

The markup was hand-authored from the smallest DOM structures required by the
production selectors. It preserves selector-bearing class names, label/value
relationships, detail links, gallery attributes, and representative text
patterns. It does not contain copied scripts, styles, consent markup, analytics,
tracking pixels, source cookies, personal seller information, or live contact
details. Names and phone numbers are clearly synthetic; vehicle image URLs are
non-routable fixture references or inert lazy-load attributes.

`expected.json` is hand-authored review data, not output generated by the parser.
Every case specifies all public facet inputs: vehicle identity, price, mileage,
condition, seller type, state, color, conversion type/manufacturer, ramp type,
and WAV features.

## Updating a fixture

1. Confirm the source markup change using an authorized observation; never paste
   a whole live page into the repository.
2. Copy only the minimum changed selector structure into a new versioned fixture.
   Remove scripts, styles, tracking markup, cookies, and personal information.
3. Keep the previous fixture when it represents a meaningful recrawl or edge
   case. Update `expected.json` manually after reviewing every changed field.
4. Run `pnpm --filter @wivwav/scraper test:fixtures`.
5. Review the fixture diff separately from the expected-output diff. A parser
   change must not silently regenerate its own expected values.

The harness creates a real Chromium page, loads fixtures with `setContent`, and
invokes the same exported `page.evaluate` functions used by production scraping.
Its fail-closed browser option aborts and fails the test on any attempted HTTP(S)
or other non-inert external request.
